# 2.2.4. Блок обновления

Блок обновления отвечает за две операции: обнаружение совпадения значения
счётчика со значением регистра `RTCMR` и загрузку нового значения счётчика
из регистра `RTCLR`.

## Обнаружение совпадения

На каждом шаге счёта текущее значение счётчика сравнивается с содержимым
`RTCMR`. Если значения равны, устанавливается бит `RTCRIS[0]` — сырой флаг
прерывания.

Флаг остаётся установленным до тех пор, пока программное обеспечение
не запишет единицу в `RTCICR[0]`. Повторное совпадение может произойти
только после полного оборота счётчика (2³² шагов), поэтому одного сброса
флага достаточно, чтобы снять запрос.

## Загрузка значения

Запись в `RTCLR` передаёт новое значение в блок обновления. В ближайший
такт `CLK1HZ` счётчик принимает это значение, и дальнейший счёт продолжается
с него.

Загрузка не влияет на флаг прерывания напрямую, но может изменить результат
сравнения: если новое значение равно `RTCMR`, совпадение будет обнаружено
на следующем шаге счёта и флаг установится.

## Маскирование

Блок обновления формирует только «сырой» флаг. Маскирование выполняет
отдельная логика: значение `RTCRIS` логически умножается на `RTCIMSC`,
результат записывается в `RTCMIS` и подаётся на выход `RTCINTR`.

```text
   счётчик ──┐
             ├──[ = ]──▶ RTCRIS[0] ──┐
   RTCMR  ───┘                       ├──[ AND ]──▶ RTCMIS[0] ──▶ RTCINTR
                        RTCIMSC[0] ──┘
```

## Замечание о задержке

Путь от совпадения до выхода `RTCINTR` проходит через синхронизатор доменов,
поэтому сигнал появляется через несколько тактов `PCLK`. Это не влияет
на корректность: флаг в регистре `RTCRIS` устанавливается независимо
от синхронизации и не теряется.
