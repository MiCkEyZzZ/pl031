# Приложение A. Описание сигналов

В приложении перечислены все сигналы контроллера: сигналы шины AMBA APB
и внутрикристальные сигналы, не относящиеся к шине.

## A.1. Сигналы AMBA APB

Контроллер подключён к шине AMBA APB как ведомое устройство.

| Сигнал | Тип | Источник / приёмник | Назначение |
|--------|-----|---------------------|------------|
| `PCLK` | вход | Генератор тактов | Тактовый сигнал APB; синхронизирует все передачи по шине |
| `PRESETn` | вход | Контроллер сброса | Сброс шины, активен низким уровнем |
| `PSEL` | вход | Мост APB | Высокий уровень означает, что контроллер выбран мостом APB |
| `PENABLE` | вход | Мост APB | Разрешение передачи; удерживается высоким в течение одного такта `PCLK` |
| `PWRITE` | вход | Мост APB | 1 — запись, 0 — чтение; синхронен с адресом |
| `PADDR[11:2]` | вход | Мост APB | Часть адресной шины APB; задаёт слово внутри блока |
| `PWDATA[31:0]` | вход | Мост APB | Однонаправленная шина данных записи |
| `PRDATA[31:0]` | выход | Мост APB | Однонаправленная шина данных чтения |

### Замечания

- Адрес передаётся только битами `[11:2]`: младшие два бита не нужны,
  так как все регистры выровнены по границе 32-битного слова.
- Диапазон `PADDR[11:2]` покрывает 4 КБ адресного пространства, чего
  достаточно для всех регистров контроллера.
- Сигналы `PSEL` и `PENABLE` должны быть активны одновременно, чтобы
  передача состоялась.

## A.2. Внутрикристальные сигналы

В таблице приведены сигналы, не относящиеся к шине.

| Сигнал | Тип | Источник / приёмник | Назначение |
|--------|-----|---------------------|------------|
| `CLK1HZ` | вход | Генератор тактов | Тактовый сигнал 1 Гц; именно он увеличивает счётчик в штатном режиме |
| `nRTCRST` | вход | Контроллер сброса | Сброс ядра RTC, активен низким уровнем. Может подаваться асинхронно, но сниматься должен синхронно с `CLK1HZ` |
| `nPOR` | вход | Контроллер сброса | Сброс по включению питания для `RTCMR` и регистров смещения. Эти регистры должны сохранять значение при сбросе шины `PRESETn` |
| `RTCINTR` | выход | Контроллер прерываний | Запрос прерывания. Высокий уровень означает, что произошло совпадение счётчика с регистром `RTCMR` |
| `SCANENABLE` | вход | Тест-контроллер | Зарезервирован под сигнал разрешения scan-режима |
| `SCANINPCLK` | вход | Тест-контроллер | Зарезервирован под вход данных scan-цепочки домена `PCLK` |
| `SCANOUTPCLK` | — | Тест-контроллер | Зарезервирован под выход данных scan-цепочки домена `PCLK` |
| `SCANINCLK1HZ` | вход | Тест-контроллер | Зарезервирован под вход данных scan-цепочки домена `CLK1HZ` |
| `SCANOUTCLK1HZ` | — | Тест-контроллер | Зарезервирован под выход данных scan-цепочки домена `CLK1HZ` |

### Замечания

- Сигналы `SCAN*` в текущей ревизии являются зарезервированными
  (place holder) и не описаны как функциональные. Направление сигналов
  `SCANOUT*` при интеграции определяется схемой тест-контроллера.
- `nRTCRST` и `nPOR` — разные сигналы: первый сбрасывает ядро счёта,
  второй — регистры, переживающие сброс шины. Объединение допустимо,
  если сохранение будильника не требуется.
- `RTCINTR` имеет единственный источник — блок обновления; прерывание
  снимается записью в `RTCICR`.

## Сводка по доменам тактирования

| Домен | Сигналы |
|-------|---------|
| `PCLK` | `PCLK`, `PRESETn`, `PSEL`, `PENABLE`, `PWRITE`, `PADDR`, `PWDATA`, `PRDATA`, `RTCITCR`, `RTCITIP`, `RTCITOP` |
| `CLK1HZ` | `CLK1HZ`, `nRTCRST`, счётчик, логика сравнения |

Регистры `RTCMR`, `RTCLR`, `RTCCR`, `RTCIMSC` доступны из домена `PCLK`,
но их значения применяются в домене `CLK1HZ` через блок синхронизации.
