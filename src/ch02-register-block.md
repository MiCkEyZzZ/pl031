# 2.2.2. Блок регистров

Блок регистров содержит все программно-доступные регистры контроллера.
Именно с ним работает интерфейс APB: любое обращение по шине адресуется
одному из регистров этого блока.

## Состав

| Группа | Регистры | Смещения |
|--------|----------|----------|
| Общие | `RTCDR`, `RTCMR`, `RTCLR`, `RTCCR`, `RTCIMSC`, `RTCRIS`, `RTCMIS`, `RTCICR` | `0x000`–`0x01C` |
| Идентификация периферии | `RTCPeriphID0`–`RTCPeriphID3` | `0xFE0`–`0xFEC` |
| Идентификация PrimeCell | `RTCPCellID0`–`RTCPCellID3` | `0xFF0`–`0xFFC` |
| Тестовые | `RTCITCR`, `RTCITIP`, `RTCITOP`, `RTCTOFFSET`, `RTCTCOUNT` | `0x080`–`0x090` |

Полное описание регистров приведено в главе 3.

## Требования к сохранению значений

Не все регистры ведут себя одинаково при сбросе.

- Регистры `RTCPeriphID0-3` и `RTCPCellID0-3` жёстко заданы и не меняются.
- Регистры `RTCMR`, `RTCTOFFSET` и `RTCTCOUNT` должны сохранять значение
  при сбросе шины `PRESETn`. Они сбрасываются только сигналом `nPOR`,
  который приходит от схемы сброса по включению питания. Это позволяет
  сохранить настройку будильника при перезапуске шины.
- Остальные регистры сбрасываются сигналом `PRESETn`.

## Доступ из двух доменов

Регистры `RTCLR`, `RTCMR`, `RTCCR` и `RTCIMSC` должны быть видимы как
в домене `PCLK`, так и в домене `CLK1HZ`. Поэтому их значения проходят
через блок синхронизации, а не подаются в счётчик напрямую. Регистры
состояния (`RTCRIS`, `RTCMIS`) формируются в домене `CLK1HZ` и передаются
в домен `PCLK` также через синхронизатор.

## Зарезервированные адреса

Обращения по адресам, не занятым регистрами, не приводят к записи данных
и возвращают неопределённое значение при чтении. Программное обеспечение
не должно обращаться к зарезервированным областям.
