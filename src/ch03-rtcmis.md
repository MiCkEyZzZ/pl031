# 3.3.7. Маскированный статус прерывания RTCMIS

`RTCMIS` — регистр только для чтения, содержащий состояние прерывания
после применения маски.

## Расположение

| Параметр | Значение |
|----------|----------|
| Смещение | `0x018` |
| Тип | RO |
| Ширина | 1 бит |
| Значение после сброса | `0x00000000` |

## Битовые поля

| Биты | Имя | Тип | Описание |
|------|-----|-----|----------|
| 31:1 | — | — | Зарезервировано, читается как ноль |
| 0 | `RTCMIS` | RO | 1 — прерывание разрешено и флаг установлен |

## Описание

Значение регистра вычисляется как логическое произведение сырого статуса
и маски:

```text
RTCMIS[0] = RTCRIS[0] AND RTCIMSC[0]
```

Именно это значение определяет уровень на выходе `RTCINTR`. Если
`RTCMIS[0] = 1`, контроллер запрашивает прерывание.

## Отличие от RTCRIS

| Ситуация | `RTCRIS[0]` | `RTCIMSC[0]` | `RTCMIS[0]` | `RTCINTR` |
|----------|-------------|--------------|-------------|-----------|
| Совпадения не было | 0 | 0 | 0 | Не активен |
| Совпадение, прерывание запрещено | 1 | 0 | 0 | Не активен |
| Совпадение, прерывание разрешено | 1 | 1 | 1 | Активен |
| Флаг сброшен, прерывание разрешено | 0 | 1 | 0 | Не активен |

Таблица показывает, что маскирование влияет только на выход прерывания,
но не на сам факт события.

## Применение

Чтение `RTCMIS` в начале обработчика — стандартный способ убедиться, что
прерывание пришло именно от этого контроллера, особенно если несколько
устройств используют общую линию запроса.

```c
uint32_t mis = *(volatile uint32_t *)(RTC_BASE + 0x018);
if (mis & 1) {
    /* Обработать прерывание RTC */
}
```

## Сброс

Регистр доступен только для чтения. Чтобы сбросить `RTCMIS`, нужно сбросить
`RTCRIS` записью в `RTCICR`.
