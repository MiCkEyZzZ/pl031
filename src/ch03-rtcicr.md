# 3.3.8. Регистр сброса прерывания RTCICR

`RTCICR` — регистр только для записи, предназначенный для сброса флага
прерывания.

## Расположение

| Параметр | Значение |
|----------|----------|
| Смещение | `0x01C` |
| Тип | WO |
| Ширина | 1 бит |
| Значение после сброса | `0x00000000` |

## Битовые поля

| Биты | Имя | Тип | Описание |
|------|-----|-----|----------|
| 31:1 | — | — | Зарезервировано, читается как ноль |
| 0 | `RTCICR` | WO | Запись 1 сбрасывает прерывание; запись 0 не действует |

## Описание

Запись единицы в бит `[0]` сбрасывает флаг `RTCRIS[0]`. Запись нуля
не изменяет состояние флага — это позволяет сбрасывать отдельные биты,
не затрагивая остальные (хотя в данном контроллере значащий бит всего один).

Регистр только для записи: чтение возвращает неопределённое значение
и не должно использоваться.

## Порядок обработки прерывания

Типичный обработчик выполняет три шага:

```c
void rtc_irq_handler(void)
{
    /* 1. Проверить, что прерывание наше */
    if (!(*(volatile uint32_t *)(RTC_BASE + 0x018) & 1))
        return;

    /* 2. Сбросить флаг */
    *(volatile uint32_t *)(RTC_BASE + 0x01C) = 1;

    /* 3. Запрограммировать следующее срабатывание при необходимости */
    *(volatile uint32_t *)(RTC_BASE + 0x004) =
        *(volatile uint32_t *)(RTC_BASE + 0x000) + 60;
}
```

## Почему важен порядок

Если сбросить флаг до чтения причины, можно потерять информацию о событии.
Если не сбросить флаг вообще, выход `RTCINTR` останется активным, и после
выхода из обработчика прерывание возникнет снова — получится бесконечный
цикл обработки одного и того же события.

## Запись нуля

Запись `0` в `RTCICR` не является ошибкой, но и не выполняет никаких
действий. Некоторые драйверы используют это свойство, чтобы выполнять
«пустую» запись для синхронизации доступа к шине.
