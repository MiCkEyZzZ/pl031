# 3.3.6. Сырой статус прерывания RTCRIS

`RTCRIS` — регистр только для чтения, содержащий «сырое» состояние флага
прерывания, то есть состояние до маскирования.

## Расположение

| Параметр | Значение |
|----------|----------|
| Смещение | `0x014` |
| Тип | RO |
| Ширина | 1 бит |
| Значение после сброса | `0x00000000` |

## Битовые поля

| Биты | Имя | Тип | Описание |
|------|-----|-----|----------|
| 31:1 | — | — | Зарезервировано, читается как ноль |
| 0 | `RTCRIS` | RO | 1 — произошло совпадение счётчика с `RTCMR` |

## Описание

Бит устанавливается аппаратно в момент, когда значение счётчика становится
равным значению `RTCMR`. Флаг не зависит от регистра `RTCIMSC`
и сохраняется до явного сброса.

Запись в регистр не оказывает действия. Для сброса флага используется
регистр `RTCICR`.

## Применение в обработчике прерывания

Регистр `RTCRIS` удобно читать в обработчике, когда нужно понять причину
прерывания до сброса флага: значение `RTCMIS` показывает, что прерывание
разрешено, а `RTCRIS` — что событие действительно произошло.

```c
uint32_t raw  = *(volatile uint32_t *)(RTC_BASE + 0x014);
uint32_t mask = *(volatile uint32_t *)(RTC_BASE + 0x018);

if (raw & 1) {
    /* Совпадение произошло */
    *(volatile uint32_t *)(RTC_BASE + 0x01C) = 1; /* сброс */
}
```

## Замечание о синхронизации

`RTCRIS` формируется в домене `CLK1HZ` и передаётся в домен `PCLK` через
блок синхронизации. Поэтому между фактическим совпадением и появлением
единицы при чтении может пройти несколько тактов `PCLK`. В масштабе секунды
это незаметно, но при отладке пошаговыми командами задержку стоит учитывать.
